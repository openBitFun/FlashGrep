# Filesystem workspace architecture

Current outcome: completed; see [completion audit](filesystem_workspace_completion_audit.md) and [final results](filesystem_workspace_results.md). The dated checkpoints below preserve intermediate states and failures.

The target is the production daemon and managed/MCP entry points, not only an example.

## Required end state

- Ordinary directories and unborn Git repositories can open, build, query, watch, refresh, close and reopen without inventing a Git revision.
- Filesystem inventory and publication identities are authoritative. Git is optional metadata and an optimization for HEAD snapshots, branch detection and cache reuse.
- A shared eligibility policy covers initial inventory, watcher scopes and reconciliation, including ignore rules, hidden/binary/size rules and internal storage exclusion.
- Normal file events use scoped filesystem discovery. Deduplicated bounded queues and periodic/overflow reconciliation repair incomplete notification coverage.
- Changed batches use incremental segments and tombstones; bounded preparation and background compaction/checkpoint prevent full dirty-set reconstruction or unbounded RAM growth under sustained/bulk changes.
- Queries expose last-published versus reconciled freshness deliberately. Reconciliation/publication progress is distinct from events observed. Git transitions preserve the existing filesystem-scan behavior.
- Restart restores durable state, then reconciles offline changes. Persistence/publication failures never silently declare fresh state or lose pending changes.

## Verification required before completion

- Production daemon and managed/MCP lifecycle on plain directories and unborn Git repositories.
- Modification/addition/deletion/restoration/rename, ignore changes, dropped events, offline edits and restart recovery.
- Git branch switch, worktree handling, staged membership changes and existing branch-cache regression coverage.
- Concurrent queries during publication, durable restart, failures and bounded bulk updates.
- Targeted performance comparison of steady queries, small updates, bulk updates and restart on isolated fixtures; report measured scope and remaining limitations.
