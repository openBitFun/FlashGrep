# 文件系统工作区重构验收与性能

生产 daemon、managed client 和 MCP 已支持普通目录、未提交 Git 仓和可选 Git 优化。`--no-git` 保持指定目录范围并关闭 Git 集成。变化通过有限 watcher 队列和文件系统核对进入增量索引，提供 published/reconciled/filesystem 三种新鲜度。架构与一致性边界见 [架构说明](filesystem_workspace_architecture.md)。

## 最终版与 tgrep：50,000 文件档

下列更新耗时为三轮中位数，起点是本档第一次写文件；50k 档是在累计 10k 修改后再改 40k。查询为持久 TCP RPC 的 p50，包含输出与 JSON 处理，`全部路径`返回 50,000 个命中文件路径。

| 指标 | 普通目录 flashgrep | 普通目录 tgrep | Git flashgrep | Git tgrep |
|---|---:|---:|---:|---:|
| 写入到结果及状态收敛，秒 | 49.98 | 16.71 | 41.32 | 17.08 |
| 稀有词查询，毫秒 | 1.58 | 3.00 | 1.54 | 2.93 |
| 全部路径查询，毫秒 | 75.16 | 196.30 | 74.22 | 195.10 |
| 混合查询，毫秒 | 1.78 | 4.63 | 1.84 | 4.52 |
| 无匹配查询，毫秒 | 0.48 | 0.90 | 0.48 | 0.91 |
| 正则查询，毫秒 | 14.78 | 15.61 | 15.00 | 15.09 |
| 重启 open，毫秒 | 186.98 | 178.53 | 191.17 | 173.78 |
| 重启首次查询，毫秒 | 119.84 | 960.19 | 141.28 | 941.87 |

最终 flashgrep 包含额外合并等待窗口的峰值 RSS 为普通目录 2.39 GiB、Git 2.44 GiB；原合并策略的已观察峰值分别为 5.49/5.73 GiB。最终版在最后一档稳定查询后还有约 20.4–58.8 秒的后台合并等待，不能把结果可见等同于后台完成。旧版和 tgrep 没有等价的后台空闲观察窗口。

检索与内存表现支持保留持久化增量段和分回合合并，但大批变化吸收仍慢于 tgrep。普通目录收敛中位数也从原合并策略的 46.07 秒变为 49.98 秒；上一轮 cooperative 实验的 25.79 秒不是最终版的结果，不能用来替代。各轮波动、启动后台工作和分段历史会影响测量，此实验不能单独证明某一种存储介质的因果收益。

## 实际 Chromium 源码树补测（2026-09-10）

直接在 `/Users/user/workspace/chromium-src` 构建独立索引，flashgrep 收录 444,129 文件，tgrep 443,565 文件；不修改源码。14 组 C/C++ 查询共 392 条有效记录，完整文件集合及逐文件匹配行数与 rg 一致。

文件列表 RPC：flashgrep 4/14 组更快，tgrep 10/14 组更快，比值几何平均约 1.00；CLI 计数：flashgrep 9/14 组更快。稀有符号和无匹配查询有优势，宽匹配是明显弱项，因此前面的 50k 子集结果不能外推为全仓优势。

首次准备为 flashgrep ensure 201.88 秒、tgrep standalone index 33.37 秒，生命周期边界不同。重启打开/首查分别为 flashgrep 656.79/14.72 毫秒、tgrep 1763.98/45.02 毫秒，但后台就绪额外等待分别为 113.34 秒和 6.85 秒。全量核对成本是当前大仓架构的实际限制。
