# 内存发布重构复测

原始记录：`/Users/user/workspace/flashgrep-memory-publication-20260910`。三轮变更和重复查询报告中位数；原目录打开和首查询为单次观测。ms 为毫秒。


## 结论

- 已完成内存优先发布与后台 checkpoint 的拆分，Git 可选；磁盘准备期间的新发布和查询通过受控并发测试。旧实例、旧 base 的过期 checkpoint 与合并不能覆盖新实例；失效实例停止回收磁盘文件。
- 大批量更新仍是 tgrep 更快。50k 修改的三轮中位数：非 Git 35.81 s 对 23.47 s，Git 41.62 s 对 25.31 s。
- 宽查询和重启首查是 flashgrep 更快。50k 全量标记查询：非 Git 70.76 ms 对 192.01 ms；Git 73.14 ms 对 208.79 ms。重启首次完整查询约 147–149 ms，对照约 928–950 ms，结果均完整。
- 没有观察到纯内存增量的热查询优势。2k 无溢写对照中全量标记查询为 2.656 ms（内存）和 2.428 ms（磁盘重启后），其余查询也接近；后者会使用正常解码缓存。
- 代价是更高的阶段 RSS：最终 flashgrep 为 1,777–1,924 MiB，历史版本同阶段为 1,242–1,365 MiB；这些来自不同轮次。最终 tgrep 为 2,516–2,750 MiB。内存预算不等于进程 RSS 上限。
- 稀疏分词中移除了构造整个区间集合只为判断是否为空的重复计算，token 输出不变。跨轮性能受负载影响，不能把全部耗时下降归因于代码修改。

## 分词方式与重复计算对照

探索性单轮：每组新建相同文件集，延后 checkpoint，测三种配置/版本。sparse 与 trigram 的 token 数量、内存占用和候选选择性不同；不是纯 CPU 微基准。2k 两种分词均未溢写；10k sparse 有溢写、trigram 无溢写。每类查询各 50 次。

| 2000 | trigram / 430107 | 0.696 | 0/6 | 0.515 | 2.642 | 3.310 |
| 10000 | sparse_ngram / 430107 | 13.153 | 11/22 | 0.906 | 13.705 | 4.009 |

最终代码保留 sparse n-gram 的输出语义，改用提前返回的存在性判断，省掉 ASCII 标识符 fallback 检查的临时权重/区间列表。随机 ASCII 输入与多组长度配置共 10,752 个组合验证了它与完整区间构建的存在性等价；原有分词正确性测试亦通过。内存/磁盘存储对照使用 430107 版，与最终版查询实现一致。
